# graylog_input (Resource)

Manages a Graylog input. Inputs define how Graylog receives log messages (e.g. Syslog UDP, GELF TCP, Beats, etc.).

## Example Usage

```terraform
resource "graylog_input" "syslog_udp" {
  title  = "Syslog UDP"
  type   = "SyslogUDPInput"
  global = true

  configuration = {
    bind_address           = "0.0.0.0"
    port                   = 1514
    recv_buffer_size       = 262144
    allow_override_date    = true
    store_full_message     = false
    force_rdns             = false
    expand_structured_data = false
  }

  static_fields = {
    from_terraform = "true"
  }
}

resource "graylog_input" "gelf_udp" {
  title  = "GELF UDP"
  type   = "GELFUDPInput"
  global = true

  configuration = {
    bind_address          = "0.0.0.0"
    port                  = 12201
    recv_buffer_size      = 262144
    decompress_size_limit = 8388608
    number_worker_threads = 2
  }
}
```

## Configuration by type

`configuration` is a Dynamic HCL object. Keys are defined by Graylog for each input `type`.
Discover the full field list (required/optional, defaults, descriptions) for your cluster with:

```terraform
data "graylog_input_types" "available" {}
```

Common built-in short type names and typical keys:

| Type | Common keys |
|---|---|
| `SyslogUDPInput` / `SyslogTCPInput` | `bind_address`, `port`, `recv_buffer_size`, `allow_override_date`, `force_rdns`, `store_full_message`, `expand_structured_data` |
| `GELFUDPInput` / `GELFTCPInput` / `GELFHttpInput` | `bind_address`, `port`, `recv_buffer_size`, `decompress_size_limit`, `override_source` |
| `RawUDPInput` / `RawTCPInput` | `bind_address`, `port`, `recv_buffer_size` |
| `BeatsInput` | `bind_address`, `port`, `recv_buffer_size`, TLS-related keys when enabled |
| `KafkaInput` | broker / topic / group keys (see `graylog_input_types`) |

Use the short class name (e.g. `SyslogUDPInput`) or the full Java type. Unknown plugin types can use the FQCN.

## Schema

### Required

- `configuration` (Dynamic) HCL object passed through to Graylog. Required/optional keys depend on `type`. Discover fields for your cluster with [`graylog_input_types`](../data-sources/input_types.md) (`requested_configuration`). Common network inputs use `bind_address`, `port`, and `recv_buffer_size`; see the resource page for per-type examples.
- `title` (String) A descriptive name for the input.
- `type` (String) Graylog input type: use the short class name (e.g. `SyslogUDPInput`, `GELFUDPInput`) or the full Java type (`org.graylog2.inputs....`). Short names are expanded on create/update and collapsed in state when they match a known built-in.

### Optional

- `global` (Boolean) Whether the input runs on all nodes (`true`) or a specific node (`false`). Defaults to `true`.
- `node` (String) Node ID to run a local input on. Required when `global` is `false`.
- `static_fields` (Map of String) Static fields to add to every message received by this input.

### Read-Only

- `id` (String) The input ID assigned by Graylog.
